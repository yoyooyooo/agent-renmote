# Whitepaper Compiler

**编译**：把讨论材料转成长期宪章，而不是把它们按时间线重新排版。

## Branches

- **Create** — 从会话、附件、研究材料或已有方案创建白皮书。
- **Revise** — 用新决定修订既有白皮书，保留稳定原则并替换失效内容。
- **Audit** — 检查权威、架构中立性、边界、符合性与可检验性；用户未要求重写时，只给审计结果与修订建议。

## Steps

### 1. Bind the corpus

确定标题、范围、版本、状态、日期、语言与交付格式；缺省时从上下文推断。穷尽当前会话、附件、旧文档、真实产物与用户修正，记录不可访问或明显缺失的材料。

**完成标准：** 每类可用材料均已纳入，关键缺口已显式标记，且未读取的文件没有被当成已知事实。

### 2. Build the authority ledger

材料来自多轮讨论、多人、旧方案或相互冲突的版本时，读取 [`REFERENCE.md`](REFERENCE.md) 的“来源权威”。把关键陈述归入：正式决定、稳定期待、候选提案、实现事实、观测结果、已推翻内容或开放问题。

**完成标准：** 每个进入正文的规范性主张都有明确权威；助手建议不会自动升级为用户决定；时间较新的明确修正能够覆盖同一作用域的旧设定。

### 3. Compile the constitution

提炼：

1. 一句话定义与核心承诺；
2. 项目品类、第一性原理与价值单位；
3. 长期原则与不变量；
4. 用户、利益相关者与核心任务；
5. 核心概念及其关系、时间、版本与权威；
6. 从输入到价值的生命周期；
7. 产品体验或外部投影；
8. 核心能力契约与允许的弃权；
9. 自动化、智能与外部执行者的边界；
10. 证据、治理、评估、经济性、非目标与符合性。

读取 [`REFERENCE.md`](REFERENCE.md) 的“白皮书契约”以校准规范词、价值单位、架构中立和符合性。

**完成标准：** 十项均被明确回答；长期原则来自正式决定、稳定期待，或为核心价值成立所必需的逻辑约束；其余内容保持候选或开放问题。

### 4. Compose the deductive narrative

创建新白皮书时读取 [`TEMPLATE.md`](TEMPLATE.md)；章节难以组织或项目类型特殊时读取 [`REFERENCE.md`](REFERENCE.md) 的“叙事架构”。按“身份 → 价值 → 原则 → 概念 → 生命周期 → 能力 → 权威 → 评价 → 边界 → 符合性”写作。章节先给结论，再说明理由、约束与影响。具体技术仅作为明确标注的当前选择、适配器或非规范示例。

**完成标准：** 未读过原始讨论的人能够理解项目为何存在；采用不同技术栈的团队仍能据此实现同一项目身份。

### 5. Red-team and prune

读取 [`REFERENCE.md`](REFERENCE.md) 的“质量门禁”，修复来源漂移、实现偷渡、价值错位、伪共识、重复、空洞原则、未经验证的承诺与未声明的不确定性。

**完成标准：** 所有阻断门禁通过；未解决事项进入“开放问题”；正文没有靠重复制造重要性。

### 6. Deliver

默认交付完整 Markdown。用户要求文件时，以 Markdown 为规范源，并仅生成其要求的其他格式。修订分支附简短版本说明；审计分支按严重度列出发现、证据与建议。

**完成标准：** 交付物可打开，相对链接有效，章节无意外占位符；版本、状态和适用范围清楚；实现分支可使用 [`CONFORMANCE.md`](CONFORMANCE.md) 声明符合性。

## Runtime rules

- 使用“必须 / 应当 / 可以 / 候选 / 正式状态”表达不同约束强度。
- 将事实、推断、候选、正式状态与外部效果分开书写。
- 让不确定性改变行为：证据不足时保留候选、允许弃权或进入人工治理。
- 当目标文档是 PRD、ADR、路线图、发布说明或会话摘要时，采用对应文档类型；白皮书只治理长期身份与不变量。
